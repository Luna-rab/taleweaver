# CardSet 集約の設計判断

## 前提

- セットを書き換えるのは同期だけ。取得元はセットをエディションに埋め込んで返すので、全ページのカードを取り終えてからセットを集めて同期し、その後でカードを同期する。Card は、セットが同期されていなければ例外を投げる。
- Card と同じく、同期は 1 本ずつ動かし、インスタンスは 1 回の同期より長く持たない。

## 照合

sourceId で探し、見つからなければ略号で探す。セットの id が振り直された例はまだないが、カードの id は振り直されている。振り直されたときに略号の一意制約で同期全体が止まるより、同じセットとして扱うほうがよいので備えた。

略号で見つかったセットの元の sourceId が今回の取得にも残っていれば、略号が重なった別のセットなので拒否する。

## 取り下げを作らない

収録したエディションが全部取り下げられると、セットは取得元から見えなくなる。それでもエディションがセットを参照するので行は消せず、取り下げられたかどうかはエディションから分かるため、セットには取り下げを持たせない。
